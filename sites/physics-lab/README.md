# Физика в действии — веб-версия

**[Работающий сайт](https://physics-in-action-lab.young-isle-4822.chatgpt.site/)** · [Общее описание проекта](../../README.md)

Эта папка содержит версию для платформы **Sites**: интерфейс React/Vinext, обработчики ИИ в Cloudflare Workers и настройки пользователей в D1. Корневая локальная версия с LM Studio и Codex CLI находится двумя уровнями выше.

На сайте доступны 27 тем курса, 10 модулей однодневной подготовки, шесть лабораторных маршрутов, игровая площадка, импорт PDF/DOCX, чат, генерация модулей и сцены Anatomy. История занятий хранится в браузере; перенос выполняется через JSON в настройках.

## Запуск из чистой копии

Нужны Node.js **22.13+**, npm и зависимости из `package-lock.json`.

```sh
cd sites/physics-lab
npm run install:ci
npm run dev -- --port 5180 --host 127.0.0.1
```

Откройте `http://127.0.0.1:5180/`. В локальном предпросмотре предусмотрен штатный тестовый вход `/signin-with-chatgpt?return_to=/`. Опубликованная версия использует настоящий вход Sites: доверенную личность пользователя устанавливает платформа.

Курс и симуляции можно проверять без ключей. Для сохранения настроек ИИ нужны локальная база и ключ шифрования, описанные ниже.

## Провайдеры ИИ

В **Настройках → Подключение ИИ** доступны:

- OpenRouter;
- OpenAI;
- Anthropic;
- Gemini;
- DeepSeek;
- Qwen / Alibaba Cloud с выбором региона;
- NVIDIA NIM;
- Ollama Cloud или свой публичный HTTPS-домен.

Для каждого провайдера сохраняются отдельные API-ключ и модель. Можно загрузить и найти модель в каталоге или указать её идентификатор вручную. Пустое поле сохраняет прежний ключ, отдельная кнопка удаляет его. При смене адреса сервера ключ нужно ввести заново либо удалить. Проверка соединения отправляет настоящий короткий запрос и может расходовать баланс.

Размещённый сайт не обращается к `localhost` на компьютере пользователя. Для Ollama отклоняются IP-адреса, имена внутренней сети и адреса с произвольными путями/портами. Codex CLI по подписке ChatGPT и LM Studio доступны в корневой локальной версии: Workers не запускает эти процессы.

## Хранение ключей

API-ключи хранятся в D1, зашифрованы **AES-256-GCM** со случайным IV и привязкой к пользователю и провайдеру. Серверный секрет `PHYSICS_KEY_ENCRYPTION_KEY` — base64-кодировка 32 случайных байтов. Ключи не возвращаются через API настроек, не хранятся в браузере и не входят в JSON истории занятий.

Настройки разделяются по доверенному заголовку `oai-authenticated-user-id`, который Sites устанавливает после входа. Анонимные запросы к настройкам и ИИ отклоняются. Публичный доступ к курсу не даёт доступа к чужим ключам. При размещении вне Sites нужно отдельно реализовать доверенную аутентификацию; принимать этот заголовок напрямую из интернета нельзя.

Для **нового локального** окружения создайте игнорируемый файл `.dev.vars`. Команда не перезаписывает существующий ключ и не выводит его в терминал:

```sh
node --input-type=module <<'JS'
import { existsSync, writeFileSync } from 'node:fs';
import { randomBytes } from 'node:crypto';
if (!existsSync('.dev.vars')) {
  writeFileSync('.dev.vars',
    'PHYSICS_KEY_ENCRYPTION_KEY=' + randomBytes(32).toString('base64') + '\n',
    { flag: 'wx', mode: 0o600 });
}
JS
```

Для опубликованного сайта секрет задаётся через настройки окружения Sites, отдельно от исходников. **Не меняйте существующий ключ без миграции зашифрованных записей:** прежние значения станут недоступны. Локальный ключ не заменяет секрет рабочего сайта.

Схема D1 — [`db/schema.ts`](db/schema.ts), готовые миграции — [`drizzle`](drizzle). Создание таблиц не выполняется при пользовательском запросе.

## Проверка собранного сайта

Из папки `sites/physics-lab`:

```sh
npx tsc --noEmit
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_motionless_mac_gargan.sql
```

Примените миграцию **один раз к новой локальной базе**. Уже созданные таблицы повторно создавать не нужно. Подготовьте локальное окружение и запустите Worker:

```sh
cp .dev.vars dist/server/.dev.vars
npm run start -- --port 5181
```

В другом терминале, **из корня всего репозитория**:

```sh
npm ci
PHYSICS_SITE_BASE_URL=http://127.0.0.1:5181 npx playwright test --config playwright.hosted.config.ts --workers=2
```

Нужен установленный Google Chrome. Набор проверяет новый маршрут, полный курс, лаборатории, документы, чат, Anatomy и настройки провайдеров. API-провайдеры в сценариях подменяются; реальные платные вызовы не выполняются. Заголовок тестового пользователя из конфигурации допустим только для локального Worker.

## Публикация через Sites

Идентификатор существующего сайта сохранён в [`.openai/hosting.json`](.openai/hosting.json). Для новой независимой публикации создайте свой проект Sites и привяжите его идентификатор; не используйте чужую базу и секреты.

Для обновления действующего сайта используйте официальный workflow плагина Sites: открыть существующий проект → проверить и собрать → отправить точный коммит исходников → упаковать архив → сохранить версию → опубликовать. GitHub-репозиторий служит общей копией исходников; у Sites может быть отдельный репозиторий публикации. Не заменяйте его Git-метаданные.

Перед упаковкой уберите копию локальных переменных из результата предпросмотра:

```sh
node -e 'const fs=require("node:fs");const p="dist/server/.dev.vars";if(fs.existsSync(p))fs.unlinkSync(p)'
```

Сохраняйте текущую аудиторию сайта. Ключи пользователей всегда остаются личными. Не добавляйте `.dev.vars`, `.env*`, `.wrangler`, `.sites-runtime`, историю браузера или исходные пользовательские PDF в репозиторий и архив публикации.
