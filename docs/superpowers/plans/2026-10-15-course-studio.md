# Расширение курса — план реализации

**Goal:** Добавлять модули из PDF/DOCX и описания темы, показывать баллы и прохождение, обсуждать материал с выбранным ИИ и создавать дополнительные интерактивные иллюстрации Anatomy.

**Architecture:** Пользовательские модули имеют собственную проверяемую схему и неизменяемые записи ответов в IndexedDB. Локальный сервер передаёт запросы в LM Studio, OpenRouter, OpenAI, Anthropic или Gemini; ключи хранятся отдельно от учебной базы. Документы разбираются локально, перед отправкой виден извлечённый текст. Визуализация задаётся данными: два подготовленных механизма либо новая сцена из деталей, ползунков и формул. Код ответа модели не исполняется; структура проверяется, физика и компоновка новых сцен требуют просмотра.

**Tech Stack:** React/TypeScript, существующая Zod/IndexedDB, PDF.js, Mammoth, Node HTTP/Vite middleware, SVG Anatomy.

**Spec:** Запрос пользователя от 15.10.2026 в этом чате, включая пять провайдеров ИИ.

**Исполнение:** В текущем проекте последовательно; пользователь уже поручил добавить функции. Существующие данные и встроенные модули сохраняются.

## Ограничения и особые проверки

- Ключи никогда не возвращаются в браузер, экспорт или журналы; изменение ключа и его удаление доступны явно.
- Локальные API принимают только запросы с собственного происхождения, ограничивают размер/частоту/время. Облачные адреса фиксированы; адрес LM Studio разрешён только на loopback.
- Документы и ответы модели считаются данными: запрет выполнения HTML/JS, строгая схема результата, ошибки/отмена без добавления пустого модуля.
- PDF/DOCX до 10 МБ; предел 100 страниц PDF и 60000 символов текста. Скан без текста требует OCR вне приложения; ограничение явно видно.
- Результат теста и процент выполнения этапов показываются отдельно. Повторные попытки не складываются в бесконечные баллы; подсказки не создают независимого подтверждения.
- Копии ранней версии импортируются с пустыми новыми коллекциями; новые коллекции проверяются и сохраняются вместе с остальной историей.
